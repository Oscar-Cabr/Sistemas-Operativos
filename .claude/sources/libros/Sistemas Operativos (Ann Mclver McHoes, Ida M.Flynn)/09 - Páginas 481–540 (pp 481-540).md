Extensibilidad

Al saber que los sistemas operativos deben cambiar con el tiempo a fin de atender nuevos
dispositivos de hardware o nuevas tecnologías de software, el equipo de diseño decidió que
el sistema operativo debía mejorarse fácilmente. Esta característica se denomina extensibili-
dad. En un esfuerzo para asegurar la integridad del código del sistema operativo Windows,
los diseñadores separaron las funciones del sistema operativo en dos grupos: un proceso
ejecutivo privilegiado y un conjunto de procesos no privilegiados denominados "subsistemas
protegidos". El término "privilegiado" se refiere a un modo de operación del procesador. La
mayor parte de los procesadores tiene un modo privilegiado (donde se permiten todas las
instrucciones de máquina y la memoria es accesible) y un modo no privilegiado (donde no se
permiten ciertas instrucciones y la memoria del sistema no es accesible) . En la terminología
de Windows, el modo privilegiado del procesador se denomina modo de núcleo y el modo
no privilegiado del procesador, modo de usuario.

Normalmente, los sistemas operativos se ejecutan únicamente en el modo de núcleo y un
programa de aplicación se ejecuta en modo de usuario, excepto cuando llaman servicios del
sistema operativo. En Windows, los subsistemas protegidos se ejecutan en modo de usuario
como si fuesen aplicaciones, lo cual permite que los subsistemas protegidos puedan modifi-
carse o agregarse sin afectar la integridad del proceso ejecutivo.

             Portabilidad
    u
             La portabilidad se refiere a la capacidad del sistema operativo para operar en máquinas
             diferentes que usan procesadores o configuraciones diferentes con una cantidad mínima
             de recodificación. Para alcanzar este objetivo, el equipo de desarrollo del sistema Windows
             siguió cuatro directrices. Primero, se escribió en un lenguaje estandarizado de alto nivel en
             todas las máquinas. Segundo, el sistema dio cabida al hardware al que se esperaba portar
             (32 bits, 64 bits, etc.). Tercero, el código que interactuaba directamente con el hardware
             debía minimizarse para reducir errores de incompatibilidad. Cuarto, todo el código depen-
             diente del hardware debía aislarse en módulos que pudieran modificarse fácilmente cada
             que se portara el sistema operativo.

             Windows está escrito para facilitar la portabilidad a máquinas que usan direcciones lineales
             de 32 o 64 bits y cuentan con capacidades de memoria virtual. Los sistemas operativos Win-
             dows han compartido las siguientes características:

             • El código es modular. Es decir, el código que debe tener acceso a estructuras de datos y
               registros dependientes del procesador está contenido en pequeños módulos que pueden
               sustituirse por módulos semejantes para procesadores diferentes.
             • Mucho de Windows está escrito en C, un lenguaje de programación estandarizado y
               fácilmente disponible. La componente gráfica y algunas porciones de la interfaz de red
               están escritas en C++. El código en lenguaje ensamblador (que no suele ser portable) se
               usa sólo para aquellas partes del sistema que deben comunicarse directamente con el
               hardware.
             • Windows contiene una capa de abstracción (HAL), una biblioteca de enlace dinámico
               que proporciona aislamiento de dependencias del hardware proporcionadas por dife-
               rentes vendedores. HAL abstrae el hardware, como memorias caché, con una capa de
               software de bajo nivel de modo que no es necesario cambiar el código de nivel superior
               cuando se mueve de una plataforma a otra.

Compatibilidad

La compatibilidad suele referirse a la capacidad de un sistema operativo para ejecutar pro-
gramas escritos para otros sistemas operativos o para versiones anteriores del mismo siste-
ma. Sin embargo, para Windows, la compatibilidad es un tema más complicado.

      Administración de archivos
      Normalmente, un sistema operativo está asociado con la estructura de archivos particular
      que usa para dispositivos de almacenamiento masivo, como discos duros. En consecuencia,
      se habla de un sistema de archivos UNIX (inodos) o de un sistema de archivos MS-DOS
      (FAT). Aunque hay un sistema de archivos NT residente (NTFS), versiones actuales de Win-
      dows están diseñadas para ser independientes del sistema de archivos en los que operan.

      El concepto primordial de manipulación de archivos en versiones recientes de Windows, que
      se introdujo primero en UNIX, es el archivo virtual, es decir, cualquier fuente o destino de
      E/S se trata como si fuera un archivo. En Windows, los programas realizan E/S en archivos
      virtuales, manipulándolos al usar identificadores de archivos. Aunque no es un concepto
      nuevo, en Windows un identificador de archivo en realidad se refiere a un objeto archivo
      ejecutivo que representa todos los recursos y destinos de E/S. Los procesos llaman a servicios
      de objetos archivo nativos como los que se requieren para leer o escribir en un archivo. El
      administrador de E/S dirige estas solicitudes de archivos virtuales a archivos reales, direc-
      torios de archivos, dispositivos físicos o a cualquier otro destino atendido por el sistema.
      Los objetos archivo poseen nombres jerárquicos, están protegidos por seguridad basada en
      objetos, atienden sincronización y son manipulados por servicios objeto.

Servicios de directorio

La base de datos del directorio activo, almacena muchos tipos de información y funciona
corno un servicio de directorio de propósito general para una red heterogénea.

Microsoft construyó Active Directory completamente alrededor del servicio de nombre de
dominio o sistema de nombre de dominio (DNS) y el protocolo ligero de acceso a directorios
(LDAP). DNS es el servicio de nombre replicado jerárquico sobre el que se basa internet. Sin
embargo, aunque DNS es el protocolo que constituye la columna vertebral de una de las re-
des de datos más grandes del mundo, no cuenta con suficiente flexibilidad para actuar como
un directorio de empresa en sí. Es decir, DNS es primordialmente para asignar nombres de
máquina a direcciones IP, lo cual no es suficiente para un servicio completo de directorio,
que debe poder asignar nombres de objetos arbitrarios (corno máquinas y aplicaciones) a
cualquier tipo de información sobre estos objetos.

Active Directory agrupa máquinas en unidades administradoras denominadas dominios,
cada una de las cuales obtiene un nombre de dominio DNS (como pitt.edu). Cada dominio
debe tener por lo menos un controlador de dominio, que es una máquina que ejecuta el
servidor de directorio activo.

Para tolerancia a fallos y rendimiento mejorados, un dominio puede tener más de un con-
trolador de dominio, donde cada uno cuenta con una copia completa de la base de datos del
directorio de ese dominio.

Versiones actuales del sistema operativo de red Windows eliminan la distinción entre con-
troladores de dominio primarios y controladores de dominio de respaldo, haciendo más
fácil de administrar la red porque no tiene múltiples jerarquías. Los clientes del directorio
activo usan las normas DNS y los protocolos LDAP para localizar objetos en la red. Como

        Para cumplir con el nivel de seguridad C2, los sistemas operativos Windows ahora incluyen

        • Una facilidad de inicio de sesión segura que requiere que los usuarios se identifiquen al

          permita tener acceso al sistema.
        • Control de acceso discrecional que permite al propietario de un recurso determinar

        • Capacidad de auditoría para detectar y registrar eventos importantes relacionados con la

        La administración de una contraseña es la primera capa de seguridad.

        La segunda capa de seguridad trata directamente con seguridad de acceso a archivos. A
        este nivel, el usuario puede crear un archivo y establecer varias combinaciones de personas
        para tener acceso al archivo porque el sistema operativo hace distinciones entre propieta-
        rios y grupos. El creador de un archivo es su propietario. El propietario puede designar un
        conjunto de usuarios como pertenecientes al grupo y permitir que todos los miembros del
        grupo tengan acceso a ese archivo. Al revés, el propietario puede impedir que algunos de los
        miembros tengan acceso al archivo.

        Además de determinar a quién se le permite tener acceso al archivo, los usuarios pueden
        decidir qué tipo de operaciones se permite que una persona realice sobre un archivo. Por
        ejemplo, una persona puede tener acceso de sólo lectura, mientras otra puede tener privile-
        gios de lectura y escritura. Como medida final, el sistema operativo proporciona al usuario
        capacidades de auditoría que automáticamente siguen la pista de quién usa los archivos y
        cómo se usan éstos.

                               Conclusión
                               Lo que comenzó como un sistema operativo de microcomputadora, ha crecido para incluir
                               un complejo software multiplataforma que puede ser utilizado para hacer funcionar siste-
                               mas de cómputo de todos los tamaños. El éxito comercial de Windows es incuestionable
                               y sus productos continúan evolucionando en complejidad y alcance para cubrir un gran
                               número de mercados mundiales.

                               Los productos Windows son ubicuos, incluyendo Windows Embebido, Windows Automoti-
                               ve y Windows Mobile, el nombre de unas cuantas de las muchas versiones especializadas de
                               este sistema operativo. Microsoft ofrece asistencia técnica para sistemas operativos no muy
                               vendidos, como Windows NT y por supuesto MS-DOS.

                               Una palabra de advertencia: la vulnerabilidad de la seguridad de los sistemas operativos de
                               Windows, los hacen blancos populares para programadores de códigos maliciosos. Ya sea
                               que estas vulnerabilidades se deban a su enorme cuota de mercado (haciéndolo enormemen-
                               te atractivo) o a los errores en los códigos por parte de Microsoft, el resultado es el mis-
                               mo: existe una constante necesidad para todo administrador de sistemas y propietarios de
                               una computadora, de mantener proactivamente todos los sistemas de Windows tan seguros
                               como sea posible por medio del control vigilante de acceso y la administración de parches.

          específicas. El usuario envía este boleto cifrado al servidor de las aplicaciones remoto, que
          entonces puede examinarlo para verificar la identidad del usuario y autenticar al usuario.

          Confiabilidad: Capacidad de un sistema operativo para responder de manera predecible a
          condiciones de error, incluso aquellas ocasionadas por fallas de hardware; o la capacidad
          de un sistema operativo para protegerse activamente a sí mismo y a sus usuarios de daño
          accidental o deliberado por programas del usuario.

          Extensibilidad: Uno de los objetivos de diseño de un sistema operativo, que permite su fácil
          mejoramiento a medida que cambian los requerimientos del mercado.

          Interfaz gráfica de usuario (GUI): Interfaz de usuario que permite al usuario activar coman-
          dos del sistema operativo al hacer clic en iconos o menús del escritorio usando un dispositivo
          apuntador como un ratón o una pantalla táctil. Las GUI evolucionaron a partir de interfaces
          de usuario controladas por comandos.

          Kerberos: Sistema de autenticación del MIT que permite a los administradores de red admi-
          nistrar y realizar la autenticación del usuario a nivel de red.

          Modo de núcleo: Nombre dado para identificar los procesos a los que se ha otorgado acceso
          privilegiado al procesador. En consecuencia, se permiten todas las instrucciones de máquina
          y la memoria del sistema es accesible. Contrasta con el modo de usuario, más restrictivo.

          Modo de usuario: Nombre dado para indicar los procesos a los que no se ha otorgado ac-
          ceso privilegiado al procesador. En consecuencia, no se permiten ciertas instrucciones y la
          memoria del sistema no es accesible. Contrasta con el modo de núcleo menos restrictivo.

          Política de búsqueda: Reglas usadas por el administrador de la memoria virtual para deter-
          minar cuándo debe copiarse una página del disco a la memoria.

          Política de colocación: Reglas usadas por el administrador de la memoria virtual para deter-
          minar dónde debe cargarse la página virtual en la memoria.

          Política de sustitución: Reglas usadas por el administrador de la memoria virtual para de-
          terminar cuál página virtual debe eliminarse de la memoria para hacer espacio para una
          nueva.

Portabilidad: Capacidad para mover todo un sistema operativo a una máquina basada en un
procesador o configuración diferente con la menor cantidad de recodificación posible.

POSIX: Portable Operating System Interface para UNIX; una aplicación del programa de
interfaz del sistema operativo desarrollada por la IEEE para incrementar la portabilidad del
software de aplicación.

Procesadores de mensajes: Interfaz de software de red de alto nivel para pasar datos entre
procesos en un mecanismo de comunicación uno a muchos y muchos a uno. Son de utilidad
para transmitir mensajes a cualquier número de procesos.

Protocolo ligero de acceso a directorios (LDAP): Protocolo que define un método para crear
directorios de recursos en una red que pueden buscarse. Se denomina "ligero" porque es una

Servicio de nombre de dominio o sistema de nombre de dominio (DNS): Servicio de consulta
de datos de propósito general, distribuido y replicado. Su función principal consiste en la

como .com (de entidad comercial) o .edu (de institución educativa).

Sistema de archivos NT (NTFS): Sistema de archivos introducido con Windows NT que ofre-
ce servicios de administración de archivos, como administración de permisos, compresión,
registro de transacciones y la capacidad para crear un volumen único que genera dos o más
discos físicos.

Tuberías nombradas: Interfaz de software de alto nivel hacia NetBIOS, que representa la
porción de hardware en aplicaciones de red como objetos abstractos. Las tuberías nombra-

bajo el mismo mecanismo de seguridad que otros objetos ejecutivos.

           Cuando un proceso solicita páginas, Linux las carga en la memoria. Cuando el núcleo nece-
           sita el espacio de la memoria, las páginas se liberan usando el algoritmo de la menos usada
           recientemente (LRU). Linux mantiene en la memoria un área administrada dinámicamente,
           un caché de páginas, donde se insertan nuevas páginas solicitadas por los procesos, y desde
           donde se borran páginas cuando ya no son necesarias. Si alguna página marcada para ser
           borrada ha sido modificada, se vuelve a escribir en el disco; una página correspondiente a
           un archivo asignado a la memoria se vuelve a escribir en el archivo y una página correspon-
           diente a los datos se guarda en un dispositivo de intercambio. El dispositivo de intercambio
           puede ser una partición en el disco o puede ser un archivo normal. Linux muestra flexibi-
           lidad agregada con los dispositivos de intercambio ya que, de ser necesario, Linux puede
           desactivarlos sin tener que volver a arrancar el sistema. Cuando esto se lleva a cabo, todas
           las páginas guardadas en ese dispositivo vuelven a cargarse en la memoria.

           páginas. Con ciertas arquitecturas de chips, el acceso a la memoria se lleva a cabo usando
           segmentos.

          El algoritmo de remplazo de páginas es una versión ampliada de la política de remplazo de
          páginas dock analizado en el capítulo 3. En lugar de usar un bit de referencia único, Linux
          usa un byte de 8 bits para seguir la pista de la actividad de una página, lo que se denomina
          su edad. Cada que se hace referencia a una página, se incrementa esta variable edad. Detrás
          del escenario, a intervalos específicos, el administrador de la memoria verifica cada una de
          las variables de edad y disminuye su valor por uno. Como resultado, si a una página no
          se hace referencia a menudo, entonces su variable de edad desciende a cero y la página se
          vuelve candidato para remplazo si es necesario un intercambio de página. Por otra parte,
          una página que se usa a menudo tiene un alto valor de edad y constituye un buen candidato
          para intercambio. En consecuencia, puede verse que Linux usa una forma de la política de
          remplazo de la menos usada recientemente (LFU, por sus siglas en inglés).

Dispositivos de caracteres

Los dispositivos de caracteres (también denominados char devices) son aquellos a los que
puede tenerse acceso como un flujo de bytes, como puerto o monitor de comunicación, o
algún otro dispositivo alimentado por flujo de bytes. Como mínimo, los controladores para
estos dispositivos suelen implementar las llamadas al sistema abrir, cerrar, leer y escribir,
aunque a menudo se agregan llamadas adicionales. A los dispositivos de caracteres puede
accederse mediante nodos del sistema de archivos y, desde un punto de vista funcional, estos
dispositivos se ven como un área de datos normal. Sus controladores se tratan de la misma
manera que los archivos normales, con la excepción de que los controladores de los disposi-
tivos de caracteres son canales de datos que deben accederse secuencialmente.


Dispositivos de bloque

Los dispositivos de bloque son semejantes a los dispositivos de caracteres, excepto que pue-
den alojar un sistema de archivos, como un disco duro. (Los dispositivos de caracteres no
pueden alojar un sistema de archivos.) Como los dispositivos de caracteres, a los dispositivos
de bloque puede accederse mediante nodos del sistema de archivos en el directorio/dev, pero
estos dispositivos se transfieren en bloques de datos. A diferencia de la mayor parte de los
sistemas UNIX, los datos en un sistema Linux pueden transferirse en bloques de cualquier ta-
maño, desde unos cuantos bytes hasta muchos. Como los controladores de los dispositivos de
caracteres, los controladores de los dispositivos de bloque se ven como archivos normales con
la excepción de que los controladores de bloques pueden tener acceso a un sistema de archi-
vos en conexión con el dispositivo, algo que no es posible con los dispositivos de caracteres.


Interfaces de red

Las interfaces de red son diferentes a los dispositivos de caracteres y a los dispositivos de
bloque porque su función consiste en enviar y recibir paquetes de información según dirige
el subsistema del núcleo de red. Así, en lugar de llamadas leer y escribir, las funciones de los
dispositivos de red se relacionan con la transmisión de paquetes.

Cada dispositivo del sistema es manipulado por un controlador de dispositivos que está, a
su vez, bajo la dirección de un subsistema de Linux.

         Interfaces basadas en órdenes

         La sintaxis general para comandos escritos es la siguiente:

         command arguments filename
         • El command es cualquier comando legal del sistema operativo.
         • Los arguments se requieren para algunos comandos y son opcionales para otros.
         • El filename puede ser el nombre de un archivo y puede incluir una ruta relativa o
           absoluta.
         Los comandos se interpretan y ejecutan por el shell (como el Bash shell), uno de los dos
         programas más usados. Shell se conoce técnicamente como el intérprete de comandos, pero
         no sólo es un intérprete de comandos interactivo; también constituye la clave para la coor-
         dinación y combinación de los programas del sistema.



         Interfaces gráficas de usuario
